# Research Modules

一个面向科研工作的即插即用模块库。这里收集可复用、可测试、文档完整的小型工具，覆盖数据获取、清洗、分析、可视化、文献处理和实验自动化等常见场景。

> 目标：让研究者能够在几分钟内理解、安装并运行一个模块，而不必复制整套项目或重写样板代码。

## 设计原则

- **即插即用**：每个模块都能独立安装和运行。
- **接口清晰**：明确说明输入、输出、参数和错误行为。
- **最小依赖**：只引入完成任务所必需的依赖。
- **可复现**：固定关键依赖版本，并提供最小可运行示例。
- **可验证**：核心行为必须有自动化测试。
- **可引用**：记录算法、数据集和第三方实现的来源。
- **不含敏感数据**：示例仅使用公开数据、合成数据或脱敏数据。

## 目录结构

```text
research-modules/
├── modules/                  # 可复用模块
│   └── category/module-name/
├── examples/                 # 跨模块或完整流程示例
├── docs/                     # 设计规范与维护文档
├── tests/                    # 仓库级集成测试
├── .github/                  # Issue 和 Pull Request 模板
├── CONTRIBUTING.md
├── MODULE_TEMPLATE.md
├── CITATION.cff
├── LICENSE
└── README.md
```

建议的一级分类：

| 分类 | 用途举例 |
| --- | --- |
| `data-collection` | API、网页、数据库和仪器数据获取 |
| `data-processing` | 清洗、转换、抽样和特征工程 |
| `analysis` | 统计分析、模型评估和敏感性分析 |
| `visualization` | 论文图表、交互图和结果导出 |
| `literature` | 文献检索、元数据整理和引用处理 |
| `experiment` | 实验配置、批量运行和结果追踪 |
| `reproducibility` | 随机种子、环境记录和产物校验 |

## 快速开始

1. 在 `modules/<category>/<module-name>/` 中选择需要的模块。
2. 阅读模块自己的 `README.md`，确认适用范围与输入输出。
3. 按模块说明安装依赖并运行 `examples/` 中的最小示例。
4. 运行该模块的测试，确认它在当前环境中正常工作。
5. 在论文、报告或代码中按模块的引用说明注明来源。

每个模块至少应包含：

```text
module-name/
├── README.md           # 用途、接口、示例、限制和引用
├── src/                # 实现
├── tests/              # 测试
├── examples/           # 最小可运行示例
├── requirements.txt    # 或 pyproject.toml / package.json 等
└── LICENSE             # 与主仓库不同或有额外要求时提供
```

## 模块成熟度

模块 README 顶部应标注以下状态之一：

- `experimental`：探索阶段，接口可能变化。
- `stable`：接口稳定，有测试与使用记录。
- `deprecated`：不建议新项目使用，并说明替代方案。

## 收录标准

一个模块适合进入本仓库，当且仅当它：

- 解决一个边界清楚、可重复出现的科研问题；
- 不依赖贡献者本机的私有路径、账号或未公开数据；
- 提供一条可验证的最小使用路径；
- 对外部数据、模型、代码和算法给出来源及许可证说明；
- 不把大型项目整体复制进来。

详细要求见 [CONTRIBUTING.md](CONTRIBUTING.md)，创建模块时可复制 [MODULE_TEMPLATE.md](MODULE_TEMPLATE.md)。

## 安全与研究诚信

- 不要提交 API 密钥、访问令牌、受试者信息或未脱敏数据。
- 涉及人类受试者、医疗、法律或高风险决策时，模块不能替代专业审查。
- 生成式模型产生的内容应由研究者核验，并记录模型、版本、提示词和运行日期。
- 抓取网站或调用数据库前，应确认服务条款、robots 规则、许可和访问频率限制。
